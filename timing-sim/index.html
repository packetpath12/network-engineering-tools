PTP/SyncE timing chain simulator

Draw a chain of grandmaster, boundary, transparent and slave clocks, set per-hop asymmetry and noise, then simulate hours of PTP time error — servo wander, holdover drift, and ITU-T G.8273.2 class checks included. Everything runs locally in your browser; nothing is uploaded.

Simplified planning models — not a substitute for lab validation

How it works / assumptions

This is a discrete-time planning model of a PTP timing chain (1 s timestep, one two-way exchange per step). It captures the dominant effects — servo tracking, asymmetry bias, packet delay variation, oscillator wander, holdover — with honest simplifications, listed below. Simplified planning models, not a substitute for lab validation against real hardware and ITU-T test setups.

The PI servo (per slave / boundary clock)

Each slave and boundary clock steers its local clock with a proportional–integral loop driven by the two-way PTP offset measurement against its upstream master:

e[k]   = measured offset vs master (ns) — includes asym/2 bias + PDV I[k+1] = I[k] + Ki · e[k] · Δt — integrator state (ns) u[k]   = Kp · e[k] + I[k+1] — total correction (ns) f[k]   = f₀ − u[k] / (Δt · 10⁹) — fractional frequency applied x[k+1] = x[k] + f[k] · Δt · 10⁹ + w[k] — clock phase (ns); w = wander noise

Defaults Kp = 0.3, Ki = 0.02 are numerically stable at Δt = 1 s. The integrator is preloaded to cancel the configured static ppm — i.e. the model starts frequency-locked and only has to acquire phase, asymmetry bias and noise. A real cold-starting servo would show a longer pull-in transient; the chart here shows the (short) acquisition of the asymmetry bias instead.

Clock-noise approximation (disclosed)

Oscillator wander w[k] is a filtered-noise approximation of power-law clock noise: white Gaussian noise through a first-order low-pass filter (time constant τ ≈ 30 s) plus a random-walk (Wiener) component. This reproduces the right qualitative behavior — bounded fast jitter riding on unbounded slow wander — but it is not a calibrated power-law generator (real models distinguish white/flicker PM/FM and random-walk FM per ITU-T G.810, e.g. LibPLN-style generators). Treat the “quiet / typical / noisy” profiles as relative planning knobs, not as calibrated oscillator models.

Two-way exchange and asymmetry

Each exchange measures offset ≈ (t₂−t₁) − (t₄−t₃) over 2. If the master→slave path is longer than the return path by asym ns, the estimate carries a fixed bias of asym/2, which the servo obediently steers into the clock: the residual time error converges to −asym/2 per span. Asymmetry does not average out — it is a fixed floor, which is why the bottleneck analysis calls it out separately. Packet delay variation (PDV) is modeled as white Gaussian measurement noise per exchange (σ from the span’s profile); transparent clocks add their residence-time jitter to every exchange crossing them.

Holdover

At the configured GM/GPS loss time, all exchanges stop and every clock free-runs on its local oscillator: x[k+1] = x[k] + f₀·Δt·10⁹ + w[k], so a 1 ppm oscillator drifts 3.6 ms per hour. The chart shades the holdover region; the “what breaks” panel reports whether holdover or the locked chain dominates each clock’s worst case.

ITU-T G.8273.2 class checks

Pass/fail is checked against the recommendation’s noise-generation limits (1000 s, applied here over the simulated interval):

  • Class A: max|TE| ≤ 100 ns (unfiltered)
  • Class B: max|TE| ≤ 70 ns (unfiltered)
  • Class C: max|TE| ≤ 30 ns (unfiltered)
  • Class D: max|TEL| ≤ 5 ns — note this is the 0.1 Hz low-pass filtered time error, exactly as the standard defines it (this tool applies the 0.1 Hz filter before checking).

Sources: Calnex “ITU-T G.8273.2 (T-BC and T-TSC) One-Page Summary” (calnexsolutions.atlassian.net/wiki/spaces/GDW/pages/10027019/), Calnex blog “G.8273.2 Specification for Class C and D Clocks” (calnexsol.com/blog/g-8273-2-specification-for-class-c-and-d-clocks/), Red Hat OpenShift PTP documentation (Class C max|TE| ≤ 30 ns). The spec additionally defines constant-TE (cTE: A 50 ns / B 20 ns / C 10 ns) and dynamic-TE masks — not checked here.

What this model leaves out

  • No BMCA grandmaster election or topology changes mid-run; one fixed reference.
  • No SyncE/ESMC frequency layer — wander comes only from the PTP servo and oscillator models.
  • No temperature ramps, packet-loss bursts, or correlated PDV (all noise is white/Gaussian).
  • Runs are deterministic: the same seed plus the same configuration always reproduces bit-identical results (mulberry32 PRNG; the seed is shown with every result).
